# اپ product؛ کاتالوگ، واریانت و نظر

[بازگشت به راهنما](README.md)

این اپ دسته‌بندی، محصول، واریانت، تصویر، نظر و پاسخ را نگه می‌دارد. کاربر بدون ورود می‌تواند محصولات و نظرها را بخواند؛ نوشتن نظر نیازمند ورود و مدیریت کاتالوگ نیازمند `is_staff=True` است.

## مدل‌ها و قواعد

| مدل | نقش و قواعد فعلی |
| --- | --- |
| `Category` | نام و slug یکتا؛ slug به‌صورت خودکار با `slugify(name)` ساخته می‌شود |
| `Product` | UUID عمومی، دسته، نام، توضیح، قیمت اعشاری، موجودی، پرچم نمایش و زمان ایجاد |
| `Product.parent` | خالی برای محصول پایه؛ برای واریانت به محصول پایه اشاره می‌کند |
| `Product.variant_name` | عنوان واریانت مثل «مشکی - ۲۵۶ گیگابایت»؛ برای واریانت اجباری |
| `ProductImage` | فایل تصویر متعلق به محصول؛ حداکثر ۱۰ تصویر برای هر محصول |
| `Review` | یک نظر برای هر ترکیب کاربر و محصول، متن و امتیاز ۱ تا ۵ |
| `Reply` | پاسخ کاربر به نظر؛ API فقط یک پاسخ از هر کاربر روی هر نظر می‌پذیرد |

ساختار محصول دو سطح دارد؛ واریانت نمی‌تواند والد محصول دیگر باشد و محصول نمی‌تواند والد خودش شود. محصول پایه‌ای که واریانت دارد نیز نمی‌تواند به فرزند محصول دیگری تبدیل شود. ترکیب `name`، `parent` و `variant_name` نباید تکراری باشد. مدل `Product` هنگام `save` اعتبارسنجی کامل اجرا می‌کند.

محصول پایه برای معرفی و دسته‌بندی گزینه‌هاست. **خرید فقط با UUID واریانت انجام می‌شود**؛ حتی اگر فقط یک گزینه می‌فروشید، برای محصول پایه یک واریانت بسازید.

`stock` موجودی واقعی انبار و `available_stock()` موجودی پس از کسر رزرو سفارش‌های پرداخت‌نشده و دارای مهلت معتبر است. این محاسبه وضعیت و زمان سفارش را بررسی می‌کند؛ خود فیلد وضعیت رزرو در فیلتر فعلی لحاظ نمی‌شود. جزئیات در [order](order.md) آمده است.

## API عمومی کاتالوگ

| متد | مسیر | نتیجه |
| --- | --- | --- |
| GET | `/user/products/` | فهرست صفحه‌بندی‌شدهٔ محصول‌های پایه با `show=True` |
| GET | `/user/product/<uuid>/` | جزئیات یک محصول پایه یا واریانت قابل نمایش |
| GET | `/user/categories/` | آرایهٔ همهٔ دسته‌ها |
| GET | `/user/category/<category_slug>/` | شیء دسته با `id`، `name` و `slug` |

این مسیرها سهمیهٔ مشترک `product_category_read` با نرخ ۶۰ درخواست در دقیقه دارند؛ برای کاربر واردشده بر اساس شناسهٔ کاربر و برای مهمان بر اساس IP.

پارامترهای فهرست محصول:

```http
GET /user/products/?category=phones&page=1&size=20
```

`category` یک slug است؛ حذف آن یا `all` یعنی همهٔ دسته‌ها. `page` شمارهٔ صفحه و `size` تعداد رکورد است: پیش‌فرض ۲۰، حداکثر ۵۰. فهرست قالب `{"count":...,"next":...,"previous":...,"results":[...]}` دارد. جست‌وجوی متنی، مرتب‌سازی انتخابی و فیلتر قیمت پیاده نشده‌اند.

نمای خلاصهٔ یک محصول پایه در فهرست:

```json
{
  "uuid": "11111111-1111-4111-8111-111111111111",
  "category": {"id": 1, "name": "Phones", "slug": "phones"},
  "name": "گوشی نمونه",
  "description": "توضیح محصول",
  "price": "0.00",
  "review_count": 0,
  "avg_rating": 0,
  "recent_reviews": [],
  "variants": [
    {
      "uuid": "22222222-2222-4222-8222-222222222222",
      "name": "گوشی نمونه",
      "variant_name": "مشکی - ۲۵۶ گیگابایت",
      "price": "1200000.00",
      "available_stock": 5
    }
  ]
}
```

UUIDها نمونه‌اند. قیمت محصول پایه میانگین یا حداقل قیمت واریانت‌ها نیست و خودکار محاسبه نمی‌شود؛ برای نمایش قیمت گزینهٔ انتخابی از همان واریانت استفاده کنید.

در پاسخ محصول پایه، `parent_uuid`، `variant_name`، `stock` و `available_stock` حذف می‌شوند. پاسخ مستقل واریانت این چهار فیلد را دارد ولی `variants`، `recent_reviews`، `review_count` و `avg_rating` را حذف می‌کند. قیمت محصول به‌صورت رشتهٔ اعشاری برمی‌گردد.

## ایجاد و مدیریت کاتالوگ

| متد | مسیر | نتیجه |
| --- | --- | --- |
| GET، POST | `/api/admin/categories/` | مشاهدهٔ دسته‌ها یا ساخت دسته با `201` |
| GET، DELETE | `/api/admin/category/<category_slug>/` | جزئیات یا درخواست حذف دسته |
| GET، POST | `/api/admin/products/` | فهرست همهٔ محصولات/واریانت‌ها یا ساخت با `201` |
| GET، PATCH، DELETE | `/api/admin/product/<uuid>/` | مشاهده، ویرایش جزئی یا مخفی کردن محصول |

ابتدا با حساب staff از API وارد شوید. ورود به پنل `/admin/` به‌تنهایی برای این مسیرها کافی نیست.

۱. `POST /api/admin/categories/` با `{"name":"Phones"}` دسته‌ای با slug برابر `phones` می‌سازد. `id` و `slug` در serializer فقط خواندنی‌اند. برای این نمونه نام انگلیسی انتخاب شده، چون slug نام کاملاً فارسی در پیاده‌سازی فعلی ممکن است خالی شود.

۲. `POST /api/admin/products/` برای محصول پایه:

```json
{
  "category_slug": "phones",
  "name": "گوشی نمونه",
  "description": "توضیح محصول",
  "price": "0.00",
  "stock": 0,
  "parent_uuid": null
}
```

`category_slug`، `name`، `price` و `parent_uuid` در ساخت لازم‌اند. برای پایه، `parent_uuid` را صریحاً `null` بفرستید و `variant_name` را حذف یا خالی کنید. UUID واقعی پاسخ را نگه دارید.

۳. به همان مسیر برای ساخت واریانت بفرستید؛ `parent_uuid` باید UUID واقعی مرحلهٔ قبل باشد:

```json
{
  "category_slug": "phones",
  "name": "گوشی نمونه",
  "variant_name": "مشکی - ۲۵۶ گیگابایت",
  "price": "1200000.00",
  "stock": 5,
  "parent_uuid": "11111111-1111-4111-8111-111111111111"
}
```

برای تغییر موجودی واریانت، `PATCH /api/admin/product/<uuid>/` با `{"stock":8}` بفرستید. فیلتر و صفحه‌بندی فهرست مدیر مثل فهرست عمومی است، ولی همهٔ پایه‌ها، واریانت‌ها و رکوردهای مخفی را شامل می‌شود.

`DELETE` محصول حذف فیزیکی انجام نمی‌دهد؛ `show=False` می‌کند و `200` برمی‌گرداند. فیلد `show` در serializer نیست، پس برای فعال‌سازی مجدد از پنل Django استفاده کنید. PUT محصول و PATCH دسته وجود ندارند.

## نظر و پاسخ

| متد | مسیر | دسترسی و رفتار |
| --- | --- | --- |
| GET، POST | `/products/<uuid>/reviews/` | خواندن عمومی؛ ثبت نظر با ورود |
| GET، PATCH، DELETE | `/reviews/<review_id>/` | خواندن عمومی؛ تغییر/حذف توسط نویسنده یا staff |
| GET، POST | `/reviews/<review_id>/replies/` | خواندن عمومی؛ ثبت پاسخ با ورود |
| PATCH، DELETE | `/replies/<reply_id>/` | تغییر/حذف توسط نویسنده یا staff؛ GET ندارد |

ثبت نظر:

```json
{"description": "کیفیت محصول مناسب بود.", "rating": 5}
```

ثبت پاسخ:

```json
{"description": "از ثبت تجربهٔ شما ممنونیم."}
```

هر دو POST موفق `201`، PATCH موفق `200` و DELETE موفق `204` دارند. تکرار نظر یا پاسخ همان کاربر `400` می‌دهد؛ POST جایگزین ویرایش نیست. متن شامل شماره موبایل، ایمیل یا عبارت موجود در فهرست ممنوعه رد می‌شود. فیلتر عبارت‌ها مبتنی بر تطابق زیررشته است و ممکن است بخشی از یک واژه را نیز رد کند.

ثبت نظر با UUID واریانت، نظر را روی محصول پایه ذخیره می‌کند؛ اما GET نظرها این تبدیل را انجام نمی‌دهد. برای نمایش نظرهای محصول، UUID پایه را درخواست کنید. خروجی نظر شامل `id`، UUID محصول، ایمیل نویسنده، متن، امتیاز و زمان‌هاست؛ پاسخ‌ها از مسیر جداگانه خوانده می‌شوند. خرید قبلی شرط ثبت نظر نیست.

مسیرهای نظر و پاسخ از سهمیهٔ مشترک ۳۰ درخواست در دقیقه استفاده می‌کنند. نظرها و پاسخ‌ها صفحه‌بندی ندارند و از جدید به قدیم برمی‌گردند.

## تصاویر، کش و محدودیت‌های فعلی

- `ProductImage` در پنل Django قابل مدیریت است؛ API آپلود و فیلد تصاویر در پاسخ محصول وجود ندارد. فایل‌ها زیر `src/media/products/<category.name>/<product.name>/` با نام UUID ذخیره می‌شوند. پسوندهای مورد انتظار `png/jpg/jpeg/webp` با حروف کوچک هستند؛ مسیر خطای پسوند نامعتبر به‌جای raise، شیء خطا برمی‌گرداند و نیازمند اصلاح است.
- محصول‌های پایهٔ عمومی بر اساس `show` فیلتر می‌شوند، ولی آرایهٔ تو‌در‌توی `variants` این فیلتر را ندارد و حتی واریانت مخفی را ممکن است برگرداند. فیلد `show` هم در خروجی نیست. افزودن واریانت مخفی به سبد `404` می‌دهد؛ نمایش کامل وضعیت واریانت نیازمند اصلاح API است.
- مخفی کردن محصول پایه، واریانت‌های آن را خودکار مخفی نمی‌کند.
- حذف دستهٔ موجود از API همیشه `400` می‌دهد؛ کد به‌جای بررسی وجود محصول، خود RelatedManager را با `None` مقایسه می‌کند.
- ساخت دستهٔ کاملاً فارسی ممکن است slug خالی و برخورد یکتایی ایجاد کند. API امکان تعیین slug دستی ندارد؛ برای دادهٔ فعلی نام قابل slug شدن استفاده کنید.
- فهرست محصولات ۹۰۰ ثانیه کش می‌شود. سیگنال ذخیره/حذف `Product` و `Review` شمارندهٔ `products_cache_version` را بالا می‌برد تا فهرست بعدی دوباره ساخته شود.
- ایجاد/انقضای رزرو و کاهش موجودی با `QuerySet.update` در callback سیگنال محصول را اجرا نمی‌کنند؛ موجودی فهرست ممکن است تا پایان کش قدیمی بماند. جزئیات محصول بدون کش خوانده می‌شود و هنگام ایجاد سفارش، موجودی دوباره بررسی می‌شود.
- دسته‌ها ۱۸۰۰ ثانیه کش می‌شوند؛ ساخت از API کش را پاک می‌کند، ولی تغییر از admin سیگنال ابطال مخصوص دسته ندارد.
- کش پیش‌فرض ابتدا Redis را می‌خواند و فقط در صورت خطای Redis به حافظهٔ محلی برمی‌گردد. نوشتن/حذف روی هر دو انجام می‌شود. حافظهٔ محلی بین پردازه‌ها مشترک نیست و جای Redis مشترک برای OTP یا محدودیت نرخ را نمی‌گیرد.
