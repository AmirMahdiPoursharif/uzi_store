# اپ cart؛ سبد خرید

[بازگشت به راهنما](README.md)

سبد به یک کاربر واردشده تعلق دارد. سبد مهمان وجود ندارد و همهٔ مسیرها `IsAuthenticated` دارند. کاربر شناسهٔ سبد یا کاربر را در درخواست تعیین نمی‌کند؛ سرور از `request.user` استفاده می‌کند.

## مدل و رفتار داخلی

`Cart` با رابطهٔ یک‌به‌یک به کاربر وصل است و زمان ساخت/ویرایش دارد. `CartItem` به سبد و محصول وصل می‌شود و تعداد را ذخیره می‌کند. قیمت آیتم در سبد ذخیره نمی‌شود:

```text
هزینهٔ هر ردیف = قیمت فعلی محصول × تعداد
هزینهٔ سبد = مجموع هزینهٔ ردیف‌ها
```

بنابراین با تغییر قیمت محصول، قیمت سبد هم عوض می‌شود. سبد نه هزینهٔ ارسال محاسبه می‌کند و نه موجودی رزرو می‌کند؛ رزرو فقط هنگام ثبت سفارش انجام می‌شود.

سیگنال `post_save` کاربر در `signals.py` هنگام ایجاد حساب، سبد خالی می‌سازد. `CartAppConfig.ready()` این سیگنال را import می‌کند و `# noqa: F401` جلوی حذف این import دارای اثر جانبی توسط Ruff را می‌گیرد. برای کاربر قدیمیِ بدون سبد، `GET /cart/` و افزودن کالا با `get_or_create` سبد را می‌سازند.

## مسیرها

| متد | مسیر | ورودی و نتیجه |
| --- | --- | --- |
| GET | `/cart/` | دریافت سبد؛ اگر وجود نداشته باشد ساخته می‌شود؛ `200` |
| POST | `/cart/addItem/` | `product_uuid` و تعداد افزایشی `quantity`؛ `201` |
| POST | `/cart/removeItem/` | `product_uuid`؛ حذف کامل ردیف؛ `204` |

حروف بزرگ `I` در `addItem` و `removeItem` را حفظ کنید. حذف نیز با POST است، نه DELETE. برای این ویوها throttle صریح تعریف نشده و محدودیت نرخ سراسری فعال نیست.

## روش استفاده

۱. مطابق [accounts](accounts.md) وارد شوید و `GET /cart/` بزنید. پاسخ سبد شامل `id`، `user` (ایمیل)، `items`، `total_cost` و `created_at` است. سبد خالی `items: []` و هزینهٔ صفر دارد.

۲. از `GET /user/products/` یک UUID واقعی از `variants` انتخاب کنید. UUID محصول پایه برای خرید پذیرفته نمی‌شود.

۳. `POST /cart/addItem/`:

```json
{
  "product_uuid": "22222222-2222-4222-8222-222222222222",
  "quantity": 2
}
```

UUID بالا نمونه است. `quantity` را عدد صحیح مثبت بفرستید؛ در صورت حذف، پیش‌فرض یک است. اگر ردیف قبلاً وجود داشته باشد، این مقدار **به تعداد قبلی اضافه می‌شود**. مثلاً دو بار ارسال `quantity: 2`، تعداد را چهار می‌کند.

سرور موجود بودن محصول، `show=True`، واریانت بودن و کافی بودن `available_stock()` برای مجموع تعداد را بررسی می‌کند. پاسخ موفق یک آیتم است، نه کل سبد:

```json
{
  "id": 12,
  "product": {
    "uuid": "22222222-2222-4222-8222-222222222222",
    "category": {"id": 1, "name": "Phones", "slug": "phones"},
    "name": "گوشی نمونه",
    "description": "",
    "price": "1200000.00",
    "stock": 5,
    "available_stock": 5,
    "parent_uuid": "11111111-1111-4111-8111-111111111111",
    "variant_name": "مشکی - ۲۵۶ گیگابایت"
  },
  "quantity": 2,
  "total_cost": 2400000.0
}
```

`product_uuid` فقط ورودی است؛ در خروجی، شیء کامل محصول در `product` می‌آید. قیمت محصول رشتهٔ اعشاری است و هزینهٔ محاسبه‌شدهٔ سبد/آیتم توسط renderer پیش‌فرض به عدد JSON تبدیل می‌شود.

۴. برای حذف کامل همان ردیف، `POST /cart/removeItem/`:

```json
{"product_uuid": "22222222-2222-4222-8222-222222222222"}
```

پس از `204` بدنه را JSON فرض نکنید و سبد را دوباره بخوانید. کم کردن تعداد، جایگزینی مستقیم تعداد و خالی کردن یک‌جای سبد API مستقل ندارند. برای تغییر تعداد به مقدار کمتر، مسیر موجود حذف کامل و افزودن دوباره است؛ این دو درخواست یک عملیات اتمیک مشترک نیستند.

۵. برای خرید، `POST /order/create/` بزنید. سفارش از سبد فعلی ساخته می‌شود و پس از ساخت موفق، آیتم‌های سبد حذف می‌شوند. ادامه در [سند سفارش](order.md).

## خطاها و محدودیت‌ها

| وضعیت | پاسخ فعلی |
| --- | --- |
| تعداد صفر، منفی یا رشتهٔ غیرعددی | `400` |
| UUID خراب یا انتخاب محصول پایه | `400` |
| موجودی ناکافی، شامل مجموع تعداد قبلی | `400` |
| محصول ناموجود یا مخفی در افزودن | `404` |
| محصول یا ردیف ناموجود هنگام حذف | `404` |
| ورود انجام نشده یا JWT منقضی | خطای احراز هویت |

`quantity: null` یا بعضی نوع‌های غیرعددی می‌توانند به‌جای `400` خطای داخلی بدهند، چون ویو فقط `ValueError` را می‌گیرد. اعداد اعشاری نیز ممکن است توسط `int` بریده شوند؛ کلاینت فقط عدد صحیح مثبت بفرستد.

حذف کالا از `Cart.objects.get` بدون رسیدگی به سبد ناموجود استفاده می‌کند؛ برای کاربران قدیمیِ بدون سبد ابتدا سبد را با GET بسازید. پاسخ UUID نامعتبر در حذف نیز قالب استاندارد `error` ندارد.

افزودن به سبد تراکنش/قفل موجودی یا قید یکتایی `(cart, product)` ندارد؛ درخواست‌های هم‌زمان یا تکرار خودکار POST می‌توانند تعداد ناخواسته یا ردیف تکراری بسازند. در کلاینت تا دریافت پاسخ از ارسال مجدد همان عملیات جلوگیری کنید. داشتن کالا در سبد تضمین موجودی نیست؛ هنگام سفارش امکان خطای موجودی وجود دارد.
