# اپ dashboard؛ پروفایل و تنظیمات حساب

[بازگشت به راهنما](README.md)

این اپ اطلاعات تکمیلی کاربر، تغییر رمز، حذف حساب و خروج را پیاده می‌کند. همهٔ APIهای آن به کاربر واردشده تعلق دارند؛ کاربر نمی‌تواند شناسهٔ شخص دیگری را برای ویرایش بفرستد. نام dashboard در این پروژه به معنی پنل مدیریت سفارش نیست؛ آن پنل در [order](order.md) است.

## مدل و مسیرها

`Profile` با رابطهٔ یک‌به‌یک به `User` وصل است و `address`، `postal_code`، `city`، `province`، `phone` و زمان ایجاد/ویرایش دارد. جدول آن مایگریشن دارد. پروفایل هنگام اولین مشاهده یا ویرایش با `get_or_create` ساخته می‌شود.

ایمیل، نام، نام خانوادگی و تلفنی که API نمایش می‌دهد از مدل `User` می‌آیند. فیلد جداگانهٔ `Profile.phone` در جریان فعلی خواندن/ویرایش استفاده نمی‌شود.

فایل `dashboard/urls.py` خالی است؛ مسیرها در `accounts/urls.py` و با پیشوند `/api/auth/` ثبت شده‌اند:

| متد | مسیر | رفتار |
| --- | --- | --- |
| GET | `/api/auth/profile/` | ساخت پروفایل در صورت نیاز و نمایش آن؛ `200` |
| PUT | `/api/auth/update-profile/` | ویرایش فقط فیلدهای ارسال‌شده؛ `200` |
| POST | `/api/auth/change-password/` | تغییر رمز با رمز فعلی؛ `200` |
| POST | `/api/auth/delete-account/` | حذف حساب با رمز و تأیید؛ `200` |
| POST | `/api/auth/logout/` | پاک کردن کوکی‌های ورود؛ `200` |

همهٔ این مسیرها `IsAuthenticated` دارند. صفحهٔ `GET /api/auth/profile-page/` صرفاً قالب HTML آزمایشی را نمایش می‌دهد؛ داده‌های آن از API احراز هویت‌شده دریافت می‌شوند.

## مشاهده و ویرایش اطلاعات

ابتدا مطابق [سند accounts](accounts.md) وارد شوید و کوکی یا هدر JWT را بفرستید.

`GET /api/auth/profile/` فیلدهای زیر را مستقیماً در یک شیء JSON برمی‌گرداند:

```json
{
  "email": "buyer@example.com",
  "first_name": "سارا",
  "last_name": "احمدی",
  "address": null,
  "postal_code": null,
  "city": null,
  "province": null,
  "phone": "+989123456789",
  "created_at": "2026-10-08T10:00:00+03:30",
  "updated_at": "2026-10-08T10:00:00+03:30"
}
```

مقادیر و زمان‌ها نمونه‌اند. برای ویرایش جزئی نیز متد **PUT** بفرستید؛ PATCH پیاده نشده است:

```http
PUT /api/auth/update-profile/
Content-Type: application/json
```

```json
{
  "first_name": "سارا",
  "last_name": "احمدی",
  "phone": "09123456789",
  "address": "خیابان نمونه، پلاک ۱۰",
  "postal_code": "1234567890",
  "city": "تهران",
  "province": "تهران"
}
```

پاسخ ویرایش قالب `{"message":"اطلاعات با موفقیت به‌روزرسانی شد","user":{...}}` دارد. فیلدهای ارسال‌نشده باقی می‌مانند. ارسال `email` اثری ندارد؛ تغییر ایمیل در این ویو پیاده نشده است.

اطلاعات آدرس فقط در پروفایل ذخیره می‌شود. سفارش فعلی نه به این آدرس متصل است و نه نسخه‌ای از آن را ثبت می‌کند؛ تکمیل پروفایل به معنی ثبت آدرس تحویل سفارش نیست.

## تغییر رمز و حذف حساب

`POST /api/auth/change-password/`:

```json
{
  "old_password": "River!Oak47Blue",
  "new_password": "Cedar!Rain82Green",
  "confirm_password": "Cedar!Rain82Green"
}
```

رمز فعلی بررسی و رمز جدید با `set_password` ذخیره می‌شود. تطابق رمز جدید و تکرار آن و اعتبارسنجی استاندارد Django اعمال می‌شود؛ validator اضافهٔ حروف بزرگ/کوچک و کاراکتر خاص accounts در این مسیر فراخوانی نشده است. خطای ورودی یا رمز فعلی اشتباه `400` دارد. این مسیر برای کاربر واردشده است و جایگزین «فراموشی رمز» نیست؛ API فراموشی رمز وجود ندارد.

`POST /api/auth/delete-account/`:

```json
{"password": "Cedar!Rain82Green", "confirm": true}
```

حذف حساب واقعی است و `soft delete` نیست. به‌دلیل روابط `CASCADE`، پروفایل، سبد، سفارش‌ها و رکوردهای وابسته، نظرها و پاسخ‌های کاربر هم حذف می‌شوند. بعد از موفقیت کوکی‌ها پاک می‌شوند. کلاینت باید اثر حذف را قبل از ارسال این درخواست برای کاربر روشن کند.

برای خروج، `POST /api/auth/logout/` با بدنهٔ خالی کافی است؛ کوکی‌ها حذف می‌شوند، اما توکن‌ها در سرور blacklist نمی‌شوند. هر دو مسیر خروج و تغییر رمز همچنان به access معتبر نیاز دارند.

## محدودیت‌های فعلی

- `UpdateProfileView` داده را مستقیم ذخیره می‌کند و از serializer ویرایش استفاده نمی‌کند؛ اعتبارسنجی تلفن و کد پستی تعریف‌شده در serializer در این مسیر اجرا نمی‌شود.
- تلفن تکراری و بعضی ورودی‌های نامعتبر ممکن است به خطای `500` برسند. کلاینت نام‌ها را حداکثر ۱۰۰ کاراکتر، تلفن را در قالب محلی معتبر و کد پستی را ۱۰ رقم بفرستد؛ این کار جای اصلاح اعتبارسنجی سرور را نمی‌گیرد.
- ذخیرهٔ `User` و `Profile` در یک تراکنش مشترک نیست؛ اگر مرحلهٔ دوم شکست بخورد، ممکن است اطلاعات کاربر قبلاً ذخیره شده باشد.
- بدنهٔ ویرایش در لاگ چاپ می‌شود و متن خطای داخلی در پاسخ `500` قرار می‌گیرد؛ این رفتار برای بهره‌برداری واقعی نیازمند اصلاح است.
- تغییر شماره در پروفایل OTP جدید نمی‌خواهد و حساب را دوباره غیرفعال نمی‌کند.
- محدودیت نرخ صریح برای این ویوها تعریف نشده و throttle سراسری هم فعال نیست.
- `Profile` در admin ثبت نشده؛ راه فعلی مصرف‌کننده برای مدیریت اطلاعات، همین API است.
